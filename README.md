# crudocs.com

The Crudo website — a static, dependency-free site for **Crudo**, a technical and
consulting services company serving the oil and gas industry with oil field services,
tubular inspection, chemical supply and technical manpower.

Live domain: **https://crudocs.com**

## Editing and building

The build has no dependencies. Node 14+ is enough.

```bash
node build.js
```

That reads every file in `src/pages/`, wraps it in `src/layout.html` with the shared
header and footer, and writes the finished page to the repository root. It also
regenerates `sitemap.xml`.

Each page starts with a metadata block that drives its `<title>`, meta description,
canonical URL, breadcrumbs and structured data:

```html
<!--meta
{
  "title": "Page title | Crudo",
  "description": "Meta description for search results.",
  "path": "about.html",
  "nav": "about",
  "priority": 0.8,
  "crumbs": [{ "name": "About Us", "url": "about.html" }]
}
meta-->
```

| Key | Purpose |
| --- | --- |
| `title` | Browser tab and search result title |
| `ogTitle` | Shorter title for social shares (falls back to `title`) |
| `description` | Meta description, Open Graph and Twitter description |
| `path` | Output filename; also the canonical URL |
| `nav` | Which nav item to highlight (`home`, `about`, `services`, `contact`, or a service slug) |
| `crumbs` | Breadcrumb trail, used for `BreadcrumbList` schema |
| `service` | Adds `Service` schema on a service page |
| `faq` | Adds `FAQPage` schema (see `contact.html`) |
| `robots` | Override the robots meta, e.g. `"noindex, follow"` |
| `priority` | Sitemap priority |

To preview locally:

```bash
npx serve .
```

## Before this goes live — three things to fill in

1. **Contact form endpoint.** The form in `src/pages/contact.html` currently has an
   empty `data-endpoint`, so submitting opens the visitor's own email client with the
   enquiry pre-filled. That works everywhere but is not ideal. To receive submissions
   directly, create a form endpoint (Formspree, Web3Forms, Basin — all have free
   tiers) and paste the URL in:

   ```html
   <form class="form" id="enquiry-form" data-endpoint="https://formspree.io/f/xxxxxxx" ...>
   ```

   Then run `node build.js`. No other change is needed — `assets/js/main.js` handles
   the POST, the success and error states, and a honeypot field for spam.

2. **Social profiles.** `src/partials/footer.html` links to WhatsApp, email and phone.
   If Crudo has LinkedIn or other profiles, add them to the `.social` block.

3. **Company facts.** The stat strip on the homepage deliberately uses only facts that
   are verifiable from the existing site (four divisions, DS-1 categories 1–4, API
   compliance, three sectors). If you want to publish figures like years in operation,
   projects completed or certifications held, add them to `src/pages/index.html` —
   they were left out rather than invented.

## Deploying

The site is plain static files with no build step required at deploy time, so any host
works. For **GitHub Pages**:

1. Repository → **Settings** → **Pages**
2. Source: **Deploy from a branch**, branch `main`, folder `/ (root)`
3. Custom domain: `crudocs.com` (the `CNAME` file already declares it)
4. Point DNS at GitHub Pages:
   - `A` records for the apex domain → `185.199.108.153`, `185.199.109.153`,
     `185.199.110.153`, `185.199.111.153`
   - or a `CNAME` for `www` → `sureshb11.github.io`
5. Tick **Enforce HTTPS** once the certificate is issued

`.nojekyll` is present so GitHub Pages serves the files as-is.

## Notes on the build

- **No framework, no dependencies.** The whole site is HTML, one stylesheet and one
  small progressive-enhancement script. Nothing breaks with JavaScript disabled.
- **Images** are served as WebP with JPEG fallbacks via `<picture>`, and were
  re-encoded from the originals — the hero went from 884 KB to 74 KB.
- **Fonts**: Space Grotesk for headings and Inter-style UI, DM Sans for body text,
  both from Google Fonts with `display=swap`.
- **SEO**: per-page titles and descriptions, canonical URLs, Open Graph and Twitter
  cards, JSON-LD (`Organization`, `WebSite`, `WebPage`, `BreadcrumbList`, `Service`,
  `FAQPage`), `sitemap.xml` and `robots.txt`.
- **Accessibility**: skip link, landmark elements, a correct heading outline on every
  page, labelled form fields, visible focus rings, and `prefers-reduced-motion`
  support that disables all animation.
